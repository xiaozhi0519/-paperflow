# PaperFlow · 研知同行

当前为开发版本：保留设计系统、演示工作台、本地文献库、PDF.js 阅读器及 AI Provider，已加入认证、服务端文献持久化、团队空间、共享阅读、讨论线程和 AI 讨论总结。工作台的论文、进度、成员与团队动态仍为演示数据。

## 环境与运行

需要 Node.js 22.13+ 和 npm。

```bash
npm install
npm run dev:server # 启动统一后端（含 AI API）；另开终端
npm run dev        # 启动前端
```

打开终端显示的本地地址。顶部「存储模式」可明确切换本地 IndexedDB 与远程账号文献库；远程模式需要注册或登录。选择「文献库」上传 PDF，点击标题编辑信息或进入阅读器。工作台的上传入口也按当前模式导入文献库；PDF 技术验证页只在本地预览。不要同时运行占用相同端口的 `dev:server` 与 `dev:ai`；后者仅为保留的独立 AI 服务，不提供认证或文献 API。若端口被其他进程占用，请选择空闲的 `AI_PORT` 并重启两者；如果 Vite 改用了非默认端口，须将实际前端来源加入 `AI_ALLOWED_ORIGINS`。

```bash
npm run typecheck       # TypeScript 检查
npm run build           # 类型检查及生产构建
npm run preview         # 预览生产构建
npm run generate:sample # 重新生成原创 PDF 样本
npm run test:browser    # 工作台与 PDF 技术验证回归
npm run test:library    # 本地文献库与阅读器端到端测试
npm run test:backend    # 隔离临时 SQLite、真实文件系统及多账号 API 测试
npm run test:team       # 团队总结：本地假模型服务验证来源校验与持久化
npm run test:import-browser # 自启动隔离后端和生产预览，测试本地文献导入浏览器流程
npm run test:collaboration-browser # 自启动隔离前后端；双账号真实 UI、知识闭环与移动端，无模型调用
PAPERFLOW_RUN_REGRESSIONS=1 npm run test:collaboration-browser # 同时回归工作台、PDF Lab 与本地文献库
npm run test:remote-browser # 指定隔离测试服务后测试远程 UI；会创建账号和文献
npm run test:ai-server  # AI 服务安全及模拟供应商测试
npm run test:ai-browser # PDF 提取、证据和 AI 界面测试
npm run test:ai-integration # 浏览器到本地模拟供应商的完整链路
npm run test:ai-provider # 真实中转站连通性测试：会调用已配置的模型
npm run test:ai-real    # 真实论文浏览器测试：会发送论文片段并调用模型
```

`test:browser`、`test:library`、`test:remote-browser` 和 `test:ai-browser` 运行前需启动前端开发服务器；`test:remote-browser` 还需要配置 `PAPERFLOW_URL` 指向使用临时数据库的独立测试后端，测试会创建账号和上传文件，切勿指向真实用户的数据；`test:ai-browser` 依赖未配置或未启动的 AI 服务以验证本地演示。`test:ai-server`、`test:ai-integration`、`test:ai-real`、`test:team` 与 `test:import-browser` 自行启动隔离的本机测试服务；`test:import-browser` 需先执行 `npm run build`，并使用临时数据目录，不会写入 `.paperflow-data`。浏览器测试使用独立的无痕上下文，不修改已有浏览器数据；需要本机 Chrome 或 Edge，未自动找到时可设置 `CHROME_PATH`，默认测试地址为 `http://127.0.0.1:5173`，可用 `PAPERFLOW_URL` 指定其他地址。

## 文献库和存储

- 允许上传不超过 20 MB 的非空 `.pdf`，检查文件头并由 PDF.js 解析；损坏、加密或不支持的文件会提示失败。上传后标题默认取文件名，作者、年份、摘要、期刊及 DOI 由用户手动填写，不声称自动提取论文元数据。
- 可按标题或作者搜索，查看和修改信息、手动调整阅读状态、查看上次阅读页码，以及在确认后删除。删除会同时删除对应 PDF、页码、高亮、笔记、文本索引和 AI 会话。
- 实际存储为当前浏览器同源下的 **IndexedDB**：PDF 以 Blob 保存，元数据、阅读进度、高亮、笔记、文本分块和 AI 会话分别存储；创建及删除在本地 IndexedDB 事务中完成。数据库从 v1 升级至 v2 保留原有数据。正式 PDF 文件不保存在 localStorage。
- 本地模式数据只在同一浏览器、设备和站点来源下可见；清理站点数据或浏览器存储淘汰可能导致丢失。不要将其作为唯一备份。
- 远程模式使用独立的服务器数据库与文件存储，通过登录账号访问。现有 IndexedDB 数据不会被自动同步或删除；登录后可在「文献库 → 导入本地文献」（`/library/import`）使用只读扫描预览每篇文献的页码、进度、高亮和笔记数量。已存在的远程文献会标记为「已导入」并禁止重复创建；与远程文献同名但 ID 不同的本地文献标记为「标题重复」且默认不勾选，可由用户显式选择后作为副本导入；本地 PDF 缺失的条目不可导入。确认导入后逐篇上传，不覆盖远程已有文献，中断的条目单独报告，浏览器 IndexedDB 中的原始论文、文件和记录保持不变。切换模式只改变所使用的 Repository。
- 本地导入不保留原始 `createdAt`，导出的高亮和笔记按导入时的新时间写入；仅导入个人上下文的文献、高亮和笔记，不推断或重建团队共享关系。
- 未配置外部服务时，统一后端使用 `.paperflow-data/paperflow.sqlite` 和 `.paperflow-data/pdf/` 下的随机文件名保存文献，`.paperflow-data/sessions.sqlite` 保存会话；可用 `PAPERFLOW_DATA_DIR` 更改。文件经鉴权 API 读取，不以公开静态路径提供。删除文献时先在数据库建立文件删除记录，失败后启动时重试；对象存储和数据库不具备跨系统原子事务，仍需运维监控与对账。
- PostgreSQL 和 S3 兼容对象存储适配已提供，但当前环境未配置这两项服务，未进行真实外部服务联调，也未部署。详见下方配置与安全说明。

## 服务端认证、数据库与部署配置

- 未设置 `DATABASE_URL` 时使用本机 SQLite，启动时自动应用迁移；`PAPERFLOW_DATA_DIR` 默认为项目下的 `.paperflow-data`。开发环境建议设置稳定的 `SESSION_SECRET`，否则重启后登录会失效。`AI_PORT` 同时是统一后端端口，默认为 8787；修改后重启 Vite 与后端，非默认前端地址需加入 `AI_ALLOWED_ORIGINS`（逗号分隔、精确匹配）。
- 账号密码经 bcrypt 哈希；使用 express-session 服务端持久化会话、HttpOnly/SameSite=Lax Cookie、登录限流、登录后更换会话 ID，并对写请求检查 Origin。文献和团队资源的鉴权在服务端执行。空间 Owner 可添加或移除已注册成员；Member 可读取共享文献、维护自己的阅读进度、创建/回复讨论和保存讨论总结，但不能管理成员、修改文献信息或删除他人内容。团队界面支持名称、简介、详情、真实统计、成员管理和直接上传；Owner 可按已注册邮箱添加成员，也可生成有效期七天的邀请码供已登录用户加入（只存 SHA-256 哈希，可轮换/撤销），不发送邮件邀请。
- 团队文献通过 `workspace_papers` 与空间关联，同一篇文献可加入多个空间；个人高亮/笔记与团队高亮/讨论按 `workspaceId` 隔离。讨论复用高亮锚点，评论最多两层（主帖与回复），删除主帖会级联删除其回复。AI 讨论总结只支持团队空间：服务端把讨论记录和团队高亮交给模型，要求每条结论标注「论文证据 / 成员观点 / AI 推断」；论文证据必须引用团队高亮的逐字片段，成员观点必须关联真实发言 ID，无法核对的条目会被移除并返回警告。总结仅在用户预览后手动保存，不会写入或覆盖任何笔记。未配置模型时明确返回 503，不使用本地伪造总结。
- `server/migrations/001_initial.cjs`、`002_team_collaboration.cjs`、`003_research_knowledge.cjs` 定义文献、批注、笔记、讨论、团队、邀请码、知识卡片、贡献记录及会话等表，包含外键、唯一约束及索引。003 为增量迁移，不修改浏览器 IndexedDB；在内存 SQLite 验证了升级/回退/再升级保留既有团队记录，未验证 PostgreSQL。回退 003 会删除知识库和邀请码数据，不应用于真实用户数据恢复。删除论文会级联删除关联知识卡片及贡献记录；当前未提供删除整个空间的 API。
- 使用 PostgreSQL 时在服务端设置 `DATABASE_URL`，**先确认目标数据库并备份**，再执行 `npm run db:migrate`，最后启动 `npm run dev:server`。服务不会自动迁移 PostgreSQL。生产模式还要求 `NODE_ENV=production`、至少 32 字符的 `SESSION_SECRET`，以及 `S3_BUCKET`、`S3_REGION`、`S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY`；`S3_ENDPOINT` 可选，非本机地址必须使用 HTTPS。S3 Bucket 必须由运维单独配置为私有并限定服务账号权限；程序不会修改 Bucket 策略。密钥不要使用 `VITE_` 前缀或提交至仓库。
- 生产模式仅通过回环地址监听，需在受信任的 HTTPS 反向代理之后运行；代理应将 Host 设置为后端实际的 `127.0.0.1:AI_PORT` 或 `localhost:AI_PORT`，并正确提供代理协议和客户端地址。前端与 API 应同源，且公开 HTTPS 来源必须包含在 `AI_ALLOWED_ORIGINS`。当前代码尚未经生产安全审计，邮箱验证、密码重置、MFA、细粒度配额、密钥轮换、备份恢复和对象删除对账均未完成，不能视为生产就绪。
- 本机未发现可用的 PostgreSQL/S3 服务，外部适配与生产反向代理尚未实测；应先在隔离环境完成迁移、权限、私有 Bucket 和恢复测试。
- `002_team_collaboration.cjs` 新增 `workspace_papers`、讨论字段与 `discussion_summaries`。升级前务必停止写入并备份数据库。回滚会删除团队共享关系、讨论和总结数据：先备份，再在隔离环境通过 Knex 调用该迁移的 `down`；仓库未提供自动回滚命令，生产 PostgreSQL 不可直接依赖回滚恢复数据。近期在临时 SQLite 中验证了 002 的 `down → up` 可移除并重建新增表与字段；该验证**不代表**已在真实 PostgreSQL 上执行。

## PDF 阅读与限制

文献库阅读器使用保存的 PDF Blob，支持渲染、翻页、缩放、单页文本选择、按页面比例坐标保存高亮、点击高亮打开并保存关联笔记。页码在页面成功渲染后保存；重新打开时恢复上次页码，不恢复精确滚动位置。阅读状态中的「已读」需手动设置，页码占比不代表完整阅读。

扫描件或无文本层的页面不能选择文字，本阶段没有 OCR；跨页选择、复杂多栏、表格、特殊字体或旋转文本可能导致选区顺序或位置偏差。高亮覆盖区域可点击进入笔记，在已有高亮区域开始新的文本选择可能受影响。更换 PDF、跨版本迁移锚点、自动修复错位和各种 PDF/浏览器兼容性均未完成。

保留 `/pdf-lab` 技术验证页及原创双页样本。该页面使用文件 SHA-256 区分高亮，验证页文字与位置保存在 localStorage，仅用于技术验证，PDF 文件本身不存入 localStorage。已使用样本验证单行、多行、翻页、缩放、重新渲染和刷新；文献库阅读器另测试了上传样本的选区和缩放几何对齐，以及原始中文 25 页 PDF 的导入、翻页和页码恢复，不代表所有论文均已验证。

## AI 服务配置与隐私

模型配置可暂时留空，不影响文献、认证及本地检索。在项目根目录不存在 `.env` 时，可将 `.env.example` 复制为 `.env`，在服务端设置以下变量后重启 `npm run dev:server`（独立 AI 服务可用 `npm run dev:ai`）：

- `AI_BASE_URL`：可信中转站提供的 OpenAI 兼容 API 基础地址（通常包含版本路径，不包含 `/chat/completions`）；服务端自动追加该路径。仅允许 HTTPS；本机回环地址允许 HTTP，供本地模型或测试使用。
- `AI_MODEL`：中转站支持的模型名称；`AI_API_KEY`：对应密钥。仅由 Node 服务读取，不要使用 `VITE_` 前缀，也不要提交 `.env` 或将密钥写入前端代码。`.gitignore` 已排除 `.env` 和其他 `.env.*` 文件，但不能自动移除已被 Git 跟踪的文件。
- `AI_TIMEOUT_MS`：超时，默认 30000 毫秒，限制在 1000–120000 毫秒；`AI_PORT`：本机服务端口，默认 8787，修改后需重启 Vite 和 AI 服务。`AI_ALLOWED_ORIGINS` 可指定允许的前端来源（逗号分隔），默认允许本机开发和预览端口 5173、4173。

当前使用 **Chat Completions** HTTP 接口，不是 Responses API。中转站须支持 Bearer 密钥、`messages`、`max_tokens`、`temperature`，返回 `choices[0].message.content` 文本；论文功能还要求该文本遵循服务提示中的 JSON 格式。服务会检查返回的 `model` 和 `usage`：`usage` 缺失或格式不兼容时标记为 `missing` 或 `invalid`，不会伪造 token 统计；这不妨碍其他内容合格的回答。模型不支持上述参数或只提供 Responses API 时，需要在 Provider 层适配。

配置齐全只表示服务端加载了配置，不代表模型连接成功。未配置或服务未启动时，阅读器明确标记“AI 服务未连接 · 本地检索演示”；演示只展示原文，不生成或冒充模型回答。实际模型调用失败时显示错误，不自动返回伪造回答。服务区分上游 401、403、404、429、超时，以及可从状态或常见错误码识别的余额/配额不足和模型不支持；上游 404 也可能由错误的接口地址造成。未知错误格式只报告上游状态和安全的通用说明，不原样回显可能包含密钥的上游错误正文。

配置后运行 `npm run test:ai-provider`：该命令直接向中转站发送一条简短测试消息，输出真实返回内容片段、响应模型及 `usage` 校验结果，不发送论文。该调用可能计费，响应模型或 `usage` 缺失会明确标记，不能仅凭本地配置宣称真实调用成功。

只有用户主动请求时，问题、选区和最多 8 个相关文本分块才会由浏览器经本机服务发送给配置的模型供应商；PDF 文件本身不发送，但片段可能包含敏感信息，发送前请确认拥有授权并了解中转站及其上游的数据政策。本地模式的会话与索引保存在当前浏览器；远程模式仅保存在当前页面内存，刷新或退出后清除，不会自动写入 IndexedDB。最多保留 40 条会话消息；可在面板清空。每次问题独立处理，不将此前会话发送给模型。

如需自动验证真实论文的上传、精读、问答、引用和跳页，先准备有权发送给中转站的 PDF，再在 Git Bash 中运行以下命令，填写自己的本机路径与包含论文原文关键词的问题：

```bash
PAPERFLOW_PDF="本机论文的绝对路径" PAPERFLOW_QUESTION="针对该论文的问题" npm run test:ai-real
```

测试会启动独立本地服务和无痕浏览器，向中转站发送论文片段并至少发起两次可能计费的模型请求；对返回引文按页独立提取 PDF 文本进行核验，并检查点击跳页。脚本只输出响应模型、`usage` 状态和核验结果，不输出论文正文或密钥。如果问题没有词项检索命中、模型没有有效引文或 PDF 文本提取不准确，测试会失败，不会冒充成功。

统一后端只监听 `127.0.0.1`，检查 Host、Origin 和请求大小。AI 接口只校验浏览器提交的片段一致性，不从服务端文献库重新验证片段；开发模式保留原本的本地 AI 调用方式，生产模式要求登录，但仍不能将该接口视为可信的服务器端文献权限或多租户配额方案。PDF/选区是不可信数据，引用校验不能完全防止提示注入或幻觉。不要将开发服务器直接暴露公网。

## AI 精读与证据

首次请求时浏览器使用 PDF.js 按页提取文本，清理控制字符、空白和重复页首/页尾，按行距近似段落并分块；每个分块含论文 ID、页码和稳定分块 ID。本地模式存入 IndexedDB，远程模式只保存在页面内存。为限制资源，最多索引前 200 页或 1200 个分块，长论文会提示覆盖不完整；无文本层的扫描件提示不支持 OCR。多栏、表格、公式、连字、文本顺序或字体编码可能导致提取内容和阅读顺序不准确，页眉页脚清理也可能漏掉或误删内容。

检索采用本地词项匹配和少量中英关键词扩展，不是向量或语义检索，可能漏召回或误召回；没有匹配时提示无法从当前论文确认。整体解读只抽样最多 8 个分块，要求模型按研究问题、背景、方法、创新、实验、结果和局限输出，不代表通读全文。选区解释、翻译、针对选区提问会携带能对应同页的原文片段；跨分块或无法精确对应的选区会提示失败，缩短选区后可重试。模型回答可保存成与高亮关联的本地笔记。

引用包含 paperId、pageNumber、chunkId 和 quote。服务端只接受所提交分块中逐字存在的引用并由分块决定页码，未通过校验的引用不会显示；如没有可核验引用则不展示模型答案。摘录对应**清理后的提取文本**，并不保证原 PDF 字节或布局完全相同。点击卡片会跳至页码；仅在当前文本层存在唯一精确匹配时才突出显示，否则明确标注页码级定位。引用存在不代表模型推理得到证实，重要结论应回看原文。

## 团队协作与讨论总结

远程模式下从侧栏「团队空间」创建带名称与简介的团队，Owner 可按已注册邮箱添加成员，或生成邀请码让成员自行加入。空间详情支持直接上传和「添加我的文献」，同一篇文献可加入多个空间；统计来自数据库。阅读器可切换「个人私有 / 团队公开」：未指定 `workspace` 时仅访问当前账号的个人记录，即使论文来自团队也不例外。公开批注显示作者、时间、页码和引文，作者、论文所有者或团队所有者可编辑关联批注内容及删除；引用原文不可改写。成员退出后，后续团队资源请求立即被服务端拒绝；已下载到浏览器的内容无法远程收回。

阅读器「讨论」面板支持创建主帖、回复（最多两层）、关联团队高亮和删除自己的发言；Owner 与论文所有者可管理工作区内的讨论。讨论保存为普通 HTTP 记录，不是实时推送，其他成员需要刷新或重新进入面板获取最新内容。

「生成总结」仅对团队空间开放，需要服务端配置模型。总结要求每条结论标注来源：论文证据必须能对应团队高亮的逐字引文，成员观点必须引用真实发言，模型归纳的推断标记为「AI 推断」；无法核对的证据会被移除并在预览中列出警告。生成结果只进入预览，必须手动点击保存才写入服务端；再次生成或保存不会修改已有笔记。未配置模型时面板显示明确提示，不会伪造总结。自动测试使用本地假模型验证来源校验与越权，**未调用真实模型**。

删除论文会一并删除其团队共享关系、团队高亮、讨论和讨论总结；该行为已在后端测试中覆盖，但属于破坏性操作，生产环境应结合备份策略。当前不包含实时多人编辑、评论通知、跨空间讨论同步或复杂知识图谱。

## 科研知识库与人工整理

`/knowledge` 提供个人私有与团队公开知识库，支持科研笔记、研究问题、研究记录三类卡片。研究问题必须关联论文；在批注或讨论旁创建时自动绑定原文批注和讨论来源。卡片区分引用原文、成员观点与人工描述，可返回论文页码、高亮位置及对应讨论。创建者与团队所有者可编辑标题、内容及研究状态，来源与可见范围不可改写；贡献记录保留操作者、操作和时间。团队卡片不能引用私人或其他团队的批注/讨论；解除论文共享后，相应团队来源卡片不可访问。个人笔记不会随共享论文自动公开。

不依赖 AI：「人工整理研究记录」由用户填写，未配置模型时讨论总结按钮显示「AI 尚未配置」。`test:collaboration-browser` 使用两套独立无痕浏览器会话和临时 SQLite，真实点击注册、建队、邀请码加入、上传、选区批注、编辑、回复、创建卡片、源文跳转、重登及退出；主流程不通过 API 写入造数，也不 Mock 模型。浏览器中的额外只读 API 权限断言单独输出。`test:backend` 是真实 SQLite/本地文件的 API 集成测试；`test:team`、`test:ai-server` 使用本机假供应商，属于 Mock 测试，不能代表真实 AI 联调。上述隔离测试不改动用户已有浏览器数据或默认服务数据目录。
